# Bible data

| File | What it is |
|---|---|
| `translations.json` | The registry: every translation the site offers, with its licence and description |
| `kjv.json` `asv.json` `web.json` `ylt.json` `darby.json` `bbe.json` | English text, one file per translation, about 4.2 MB each (about 1.2 MB as served, compressed) |
| `rst.json` | Russian Synodal text, 6.2 MB (1.4 MB compressed); Cyrillic letters take two bytes each |
| `lxx.json` | The Septuagint (Greek Old Testament), 5.7 MB |
| `kjvs.json` | KJV+: the KJV with a Strong's number on each word, 8.1 MB (about 2.4 MB compressed) |
| `research.json` | The research data's registry: where each set is, its licence and its cache version |
| `xref/<BOOK>.json` | Cross-references, one file per book (5.8 MB in all; Psalms is the largest at 0.5 MB) |
| `strongs/hebrew.json` `strongs/greek.json` | Strong's dictionaries, 1.9 MB and 1.1 MB |
| `geo/places.json` `geo/basemap.json` | Bible places (1,309, with the verses that name them), and coastlines, lakes and rivers for the maps |
| `study/books/<BOOK>.json` `study/timeline.json` `study/maps.json` | Hand-written study pages: book introductions, the timeline, the maps' places and journeys |

The translation files are generated by `npm run build-data` from the pinned sources in `tools/data-sources.json` (see "Rebuilding" below). The research data has its own build scripts (see "Research data" below).

## Translation file format (`formatVersion` 1)

One JSON file per translation, structured book → chapter → verse:

```json
{
  "formatVersion": 1,
  "id": "kjv",
  "abbreviation": "KJV",
  "name": "King James Version",
  "language": "en",
  "direction": "ltr",
  "license": "Public domain",
  "source": "https://raw.githubusercontent.com/scrollmapper/bible_databases/…/json/t_kjv.json",
  "books": [
    {
      "id": "GEN",
      "name": "Genesis",
      "chapters": [
        ["In the beginning God created the heaven and the earth.", "And the earth was without form, and void; …"],
        ["Thus the heavens and the earth were finished, and all the host of them.", "…"]
      ]
    }
  ]
}
```

Rules:

- **`books[].id`** is the upper-case [USFM book code](https://ubsicap.github.io/usfm/identification/books.html): `GEN EXO LEV … MAT MRK LUK JHN ACT … REV`. The list is in `js/canon.js`, and the site orders books by the canon.
- **`chapters[i]`** is chapter *i + 1*; **`chapters[i][j]`** is verse *j + 1*, as plain UTF-8 text with no HTML or markup.
- **Missing verse:** use `""` so later verse numbers stay aligned (the ASV leaves Matthew 17:21 empty). Don't pad the end of a chapter.
- **Psalm titles**, where a source has them, are the start of verse 1 ("A Psalm of David. Jehovah is my shepherd…").
- **Optional: a translation's own numbering.** A translation renumbered to English verse numbers (see "Verse numbering" below) records its original scheme in `"nativeVersification"`, and gives each affected book a `"native"` object. That object says where each English chapter sits in the original numbering, for chapters where the two differ: `"native": {"23": [[22]], "10": [[9, 22, 39]], "116": [[114], [115]]}`. Each span is `[chapter]` (all of it) or `[chapter, firstVerse, lastVerse]`. The reader uses it to show, in compare mode, "Псалом 22" beside English Psalm 23.
- **Optional: Strong's numbers.** A book can carry `"tags"`, shaped like `"chapters"`, with one string per verse. Each tagged word is `start.length.number`: `"7.9.H7225 17.3.H430"` marks "beginning" (characters 7–15) as Hebrew word 7225 and "God" as 430. Offsets count UTF-16 code units, as JavaScript strings do. A word tagged with two numbers joins them with `+` (`"G3056+G5207"`). Numbers have no zero padding, so they match the dictionaries' keys. KJV+ has these tags; the provider turns them into each verse's `words`.
- **Optional: one Testament only.** A translation of just one Testament says so with `"testaments": ["OT"]` (the Septuagint). The validator and tests then expect only that Testament's books, and the reader shows "isn't included" for the other.
- **Typography:** curly quotes and apostrophes (‘ ’ “ ”), em dashes (—), no space before punctuation. The tests enforce this so parallel columns look consistent.

Check a file with `node tools/validate-translation.mjs data/kjv.json`, or check them all with `npm run validate`.

## `translations.json`

```json
{
  "default": "kjv",
  "translations": [
    {
      "id": "kjv",
      "abbreviation": "KJV",
      "name": "King James Version",
      "year": "1769",
      "language": "en",
      "direction": "ltr",
      "provider": "json",
      "url": "data/kjv.json",
      "version": "5f0fc045c265",
      "license": "Public domain",
      "copyright": "Public domain in most of the world. In the United Kingdom, …",
      "description": "The Authorized Version of 1611, …",
      "source": { "name": "scrollmapper/bible_databases", "url": "https://github.com/scrollmapper/bible_databases" }
    }
  ]
}
```

| Field | Use |
|---|---|
| `id` | Lower-case letters, digits, hyphens. Appears in URLs: `#/john/3?t=kjv,asv` |
| `abbreviation`, `name`, `year` | Dropdowns, column headings, notices |
| `license` | Short label shown under the text ("Public domain") |
| `notice` | *(optional)* Credit line a licence requires next to the text; replaces `license` there |
| `numbering` | *(optional)* For a translation with its own numbering: `name` (read to screen readers, e.g. "Synodal numbering") and the words for its Psalm labels (`psalm`, `psalms`) |
| `copyright`, `description`, `source` | The Translations page (`#/translations`) |
| `languageName` | *(optional)* The language's name on the Translations page, where browsers may not know the code (`grc`: "Ancient Greek"). Otherwise the browser names it |
| `strongs` | *(optional)* `true` when the file has Strong's `tags`: its words can be tapped for word study (KJV+) |
| `basedOn` | *(optional)* The id of the translation whose text this one shares (KJV+: `"kjv"`). "All translations" search leaves it out, so the same text isn't listed twice. It's listed last, so adding a compare column offers it last |
| `provider` | Which provider serves it: `"json"` = static file at `url`. See `js/providers/README.md` for API sources |
| `version` | First 12 hex digits of the file's SHA-256. It's the cache key: when a file changes, readers' cached copies refresh automatically. `npm run build-data` sets it, and `npm test` fails if it's stale |

## Where the text comes from, and why

Each source was chosen by comparing the candidates verse by verse and checking for conversion damage:

| | Source | Why this one | Clean-ups applied |
|---|---|---|---|
| **KJV** | scrollmapper/bible_databases, `2024` branch | The only copy checked that keeps the small-caps "LORD" (the newer branch has "The Lord is my shepherd") | typography |
| **ASV** | scrollmapper, current branch | Has Psalm titles. It correctly leaves out the 16 verses the 1901 edition moved to the margin, where the legacy file fills them in | typography, `[Selah` → `Selah` (73) |
| **WEB** | eBible.org's USFX, via seven1m/open-bibles | The legacy JSON is unusable (inline footnotes, `\"`, Romans 16:27 replaced by a note). This is the publisher's own text: footnotes dropped, Psalm titles kept, Apocrypha skipped | none needed |
| **YLT** | scrollmapper, current branch | Has Psalm titles and fewer leftover marks than the legacy file | typography (backtick quotes → ‘ ’, `--` → —) |
| **Darby** | scrollmapper, current branch | The only copy available | typography, missing space before "God"/"Godhead" restored (3,681) |
| **BBE** | scrollmapper, current branch | The legacy file uses Hebrew verse numbers in places (Leviticus 5:20–26, Job 39:31–38), which breaks alignment | typography |
| **LXX** | eBible.org's *Brenton Greek Septuagint* (`grcbrent`, USFX zip) | The Greek text Brenton printed in 1851 (Codex Vaticanus, as in the Sixtine edition), public domain. Its numbering matches the Copenhagen `lxx` scheme in 1,074 of its chapters, against 982 for eBible's other public-domain Greek Septuagint (`grclxx`), so it can be renumbered reliably | renumbered to English verse numbers (below); square brackets dropped (`drop-brackets`, 3 places); `capitalize-chapter-start` (2) |
| **KJV+** | eBible.org's *King James Version* with Strong's numbers (`eng-kjv2006`, USFX zip) | The only public-domain KJV with a Strong's number on (nearly) every word: 349,308 tags, using 14,057 numbers, all of them in the dictionaries | `drop-pilcrows` (the ¶ paragraph marks, 2,970); Strong's numbers kept as `tags` (`wordTags`); Psalm titles at the start of verse 1, like the other sources |
| **RST** | scrollmapper, current branch (`RusSynodal.json`) | Consistently in Synodal numbering (all 1,192 chapters match the `rso` scheme), so it can be renumbered exactly. The other copy checked (open-bibles' Zefania XML) mixes numbering systems. Wording agrees with it in 99.1% of New Testament verses; the rest are spelling variants | renumbered to English verse numbers (below); `russian-typography` (` - ` → ` — `, straight quotes → «», one quote typed as `::`); `capitalize-chapter-start` (24 Psalm titles began in lower case); footnotes dropped; a Psalm title stuck to the end of the previous Psalm moved back; Psalm 114:8–9 (Synodal), which the source runs together, split again (`splitVerses`) |

Clean-ups only change typography or repair conversion damage. They're defined in `tools/lib/translation-file.mjs`. The pinned URLs are in `tools/data-sources.json`. eBible.org doesn't version its downloads, so for the LXX the file records the SHA-256 of the zip that was used instead, and `build-data` warns if a new download differs.

### Verse numbering (versification)

All data files use **English (KJV) chapter and verse numbers**, so `#/psalms/23` means the same passage in every translation, and parallel columns line up. The Russian Synodal numbers some passages differently: most Psalms are one lower (the Shepherd psalm is Псалом 22), Psalm titles count as verses, Joel 2:28–32 is chapter 3, and Romans 16:25–27 sits at 14:24–26. So `rst.json` is renumbered when it is built:

- **Mappings:** the [Copenhagen Alliance versification mappings](https://github.com/Copenhagen-Alliance/versification-specification) (CC BY-SA 4.0), which map each scheme to the original-language numbering, giving Synodal (`rso`) → original → English (`eng`). They're downloaded at build time and not stored in this repository.
- **Two-verse titles:** where one English verse covers two Synodal verses, their text is joined. A title that has no number in English starts verse 1, as in the other translations.
- **Corrections:** checking every chapter against the KJV turned up five errors in `rso.json` (Isaiah 3:19–26, Daniel 5:31–6:28, 2 Corinthians 13:13, 3 John 1:15, Psalm 114:9). Each was confirmed by reading the Russian and English text side by side. They're fixed by the `corrections` in `tools/data-sources.json`, which are offered under the same CC BY-SA 4.0 licence.
- **Native numbering:** the original chapter of every renumbered verse is kept as each book's `native` spans (format above). In compare mode, a Psalm column whose numbering differs shows it under its dropdown: "Псалом 22", "Псалом 9:22–39", "Псалмы 114–115". The label words come from the translation's `numbering` entry in `translations.json`.
- **Tests:** `tests/versification.test.js` and `tests/numbering.test.js` cover the method, and `tests/data.test.js` spot-checks the result.

**The Septuagint** (`lxx.json`) is renumbered the same way, from the `lxx` scheme:

- **Psalms:** numbered as in the Synodal (Greek Psalm 22 is English 23).
- **Jeremiah:** the Septuagint order of chapters 25–51.
- **3 Kingdoms 20–21:** swapped relative to English.
- **Greek Daniel and Esther, and 2 Esdras:** Daniel and Esther become the English books, and 2 Esdras becomes Ezra and Nehemiah.
- **Corrections:** where Brenton's numbering differs from the scheme, or the mapping is incomplete, there are eight, each checked against the Greek text:
  - **Deuteronomy 29:** numbered as in English.
  - **Proverbs 24:35–62:** Brenton's numbers for 30:15–33 and 31:1–9.
  - **1 Kings 20 ↔ 21:** the mapping moves only one way.
  - **Nehemiah 7:73:** missing from the mapping.
  - **Exodus 36–39:** see "Known gaps".
  - **Daniel 3:24–90:** see "Known gaps".
- **Lettered verses:** Brenton marks the Septuagint's additions as lettered verses (Proverbs 9:18a–d). They stay with the verse they follow. Brenton also numbers Proverbs 30:1–14 as 24:22f–t, which the `relabel` option in `tools/data-sources.json` moves back.

To renumber another translation, add `"versification": { "scheme": "<scheme>" }` to its source. Schemes include `rso` (Russian Orthodox/Synodal), `rsc` (Russian Protestant), `lxx` and `vul`. `corrections` override the scheme verse by verse.

### Known gaps in the text

- **Psalm titles:** KJV and BBE have none (their sources lack them); ASV, WEB, YLT and Darby put them at the start of verse 1.
- **KJV:** some hyphenated names lost their hyphen ("Beersheba"), and there are rare small-caps slips (Psalm 3:1 "Lord" for "LORD"). Italics and paragraph marks are not included.
- **WEB:** footnotes and section/acrostic headings are not shown. Its New Testament follows the Majority Text, so Romans 16 ends at verse 24 (the closing doxology is at 14:24–26).
- **Darby:** keeps its own square brackets for words added for sense. Some acrostic letter names (ALEPH, BETH…) appear at the start of verses in Psalm 119.
- **RST:**
  - Verse numbers are English, so they differ from printed Russian Bibles in the Psalms and a few other places. The book names in the interface are English too.
  - Passages outside the 66-book canon are left out: Psalm 151, Daniel 13–14, and the Song of the Three in Daniel 3.
  - Septuagint additions kept as extra verses beyond the English count: Joshua 24:34–36 and Proverbs 4:28–29.
  - Square brackets mark words added for sense or taken from the Septuagint, as in the printed edition. Job 42:17 includes the edition's appendix from the Slavonic Bible.
  - Footnotes are not shown.
  - Where one Russian verse covers two English ones (e.g. Acts 19:40–41), the second shows a dash in parallel view.
- **LXX (Septuagint):**
  - **Coverage:** Old Testament only, and only the 39 books shared with English Bibles. Tobit, Judith, Wisdom, Sirach, Baruch, the Letter of Jeremiah, Susanna, Bel and the Dragon, 1–4 Maccabees, 1 Esdras, the Prayer of Manasseh and Psalm 151 are in the source but left out, because the site's canon has no place for them yet.
  - **Additions kept in the text:** Greek Esther and Daniel are kept whole. Esther's additions stay inside the verse they follow (Mordecai's dream is part of 1:1). The Prayer of Azariah and the Song of the Three (Daniel 3:24–90 in Greek) are kept with Daniel 3:23, where they stand, so that verse is long.
  - **Exodus 36–39:** the Greek arranges the building of the tabernacle in a different order, and the mapping covers only part of it. These chapters keep the Greek's own chapter and verse numbers, so in compare view they don't line up with English Bibles there.
  - **Verses not in the Greek:** they show as a dash in compare view. Examples: Nehemiah 4:6, and much of Jeremiah, which is about an eighth shorter in Greek.
  - **Typography:** first words of chapters and some headings are in capitals, as Brenton printed them ("ἘΝ ἀρχῇ").
  - **Footnotes:** not shown.

## Rebuilding and adding translations

```bash
npm run build-data
```

That rebuilds all nine. Add ids to rebuild only some, as in `npm run build-data -- asv rst`. Downloads are cached in `.cache/sources/`, which git ignores. Behind a proxy (as in some cloud sandboxes), Node needs `NODE_USE_ENV_PROXY=1` to use it.

To add another public-domain translation:

1. Add an entry to `translations.json` (id, names, licence, `"provider": "json"`, `"url": "data/<id>.json"`).
2. Add its source to `tools/data-sources.json`, with `"format": "scrollmapper"` (their JSON), `"usfx"` (eBible.org's XML), or `"usfx-zip"` (eBible.org's zipped download, with `"entry"` naming the XML file and `"sha256"` the zip). Add any clean-ups it needs, a `"versification"` scheme if it doesn't use English verse numbers, and `"testaments": ["OT"]` if it has only one Testament.
3. Run `npm run build-data -- <id>`, then `npm test`. The data tests check every listed translation automatically.

For a one-off conversion, `tools/convert-scrollmapper.mjs` and `tools/convert-usfx.mjs` do the same job from the command line.

## Research data

Each set is built from pinned sources in `tools/research-sources.json`. Each build writes the content version that the site uses as its cache key into `research.json`, and `npm test` checks the versions are current.

| Build | Writes | Source |
|---|---|---|
| `node tools/build-xref.mjs` | `xref/` | OpenBible.info cross-references (CC BY) |
| `npm run build-data -- kjvs` | `kjvs.json` | eBible.org's KJV with Strong's numbers (public domain; tagging by the CrossWire Bible Society) |
| `node tools/build-strongs.mjs` | `strongs/` | Open Scriptures' Strong's dictionaries (CC BY-SA) |
| `node tools/build-geo.mjs` | `geo/` | OpenBible.info Bible Geocoding Data (CC BY 4.0); Natural Earth 1:10m (public domain) |
| `node tools/build-study.mjs` | the `study` version | the hand-written files in `study/` |

### Cross-references: `xref/<BOOK>.json`

```json
{ "formatVersion": 1, "book": "JHN", "verses": {
"3:16": [["ROM 5:8", 995], ["1JN 4:9-10", 707], ["ROM 8:32", 517], …],
… } }
```

Each verse of the book (`"chapter:verse"`, English numbering) lists `[reference, votes]`, best first. The votes are OpenBible.info readers' votes for how helpful the reference is. References look like `"ROM 5:8"`, `"1JN 4:9-10"` or `"GEN 11:32-12:1"` (USFM book id, then chapter:verse, with an optional range that can cross into the next chapter). `js/research/refs.js` reads them.

From the source's 344,800 rows, these were dropped:
- references with no votes or negative votes (3,416);
- one reference to a verse the KJV doesn't have.

The 17 ranges that ran from one book into the next (`2Chr.36.22-Ezra.1.3`) became one reference in each book (`2CH 36:22-23` and `EZR 1:1-3`). In all, 341,399 references remain.

### Strong's dictionaries: `strongs/hebrew.json`, `strongs/greek.json`

```json
{ "formatVersion": 1, "language": "hbo", "entries": {
"H7225": { "lemma": "רֵאשִׁית", "xlit": "rêʼshîyth", "pron": "ray-sheeth'",
           "def": "the first, in place, time, order or rank (specifically, a firstfruit)",
           "kjv": "beginning, chief(-est), first(-fruits, part, time), principal thing.",
           "deriv": "from the same as H7218 (רֹאשׁ);" },
… } }
```

The fields are:
- `lemma`: the Hebrew or Greek word.
- `xlit`: its transliteration.
- `pron`: a pronunciation guide (Hebrew only).
- `def`: Strong's definition.
- `kjv`: how the KJV renders the word.
- `deriv`: where the word comes from.

Links to other entries (`H7218`) lose their zero padding. The Greek source's symbols are written out: "X" becomes "[idiom]" and "+" becomes "[phrase]", as the Hebrew source already does. Six wrong links in the Greek source are corrected; each correction is listed in `tools/research-sources.json`. Every Strong's number used in KJV+ has an entry.

### Places: `geo/places.json`

```json
{ "formatVersion": 1, "places": {
"a15257a": { "name": "Jerusalem", "type": "settlement", "lon": 35.2342, "lat": 31.7767,
             "score": 500, "slug": "jerusalem", "verses": ["JOS 10:1", …], "ru": "Иерусалим" },
… } }
```

The fields are:
- Keys are OpenBible.info's place ids.
- `type` is settlement, region, mountain, river, island, body of water, and so on.
- `score` is OpenBible.info's confidence in the identification: 500 or more is high, under 300 is uncertain.
- `verses` lists where the Bible names the place.
- `ru` is the Russian (Synodal) name, from `tools/place-names.json`. Only the places the maps and study pages use have one; others show their English name in the Russian interface.

### Basemap: `geo/basemap.json`

```json
{ "formatVersion": 1, "bounds": [8, 23.8, 54, 46],
  "land": [[lon, lat, lon, lat, …], …],
  "lakes": [{ "name": "Dead Sea", "rings": [[…]] }],
  "rivers": [{ "name": "Jordan", "lines": [[…]] }] }
```

The basemap is Natural Earth's land, natural lakes and Bible rivers, clipped to the box from Rome to Persia. It's simplified to about 300 m around Israel and 1.5 km elsewhere, and rounded to 3 decimals: 87 kB in all.

### Study content: `study/`

- **`books/<BOOK>.json`:** one introduction per book. The fields are:
  - `author`, `date`, `summary`, each `{ "en", "ru" }`.
  - `themes`: 3–6 entries, each `{ "en", "ru" }`.
  - `outline`: sections, each `{ "ref": "GEN 1:1-11:26", "en", "ru" }`. They must cover the whole book, in order, with no gaps or overlaps.
  - `keyVerses`: references.
  - `places`: optional place ids.
- **`timeline.json`:** `eras`, each `{ id, start, end, title, dates }`, and `events`, each `{ id, era, year, date, title, summary, refs, place }`. Years are whole numbers, with BC negative. `date` is the label shown, which carries any uncertainty ("c. 1446 or c. 1260 BC").
- **`maps.json`:** each map has these fields:
  - `id`, `title`, `summary`.
  - `bounds` `[west, south, east, north]`, which must lie inside the basemap.
  - `places`: the ids it labels.
  - `labels`: region, water and river names, each with a lon/lat.
  - `routes`: optional journeys, each `{ id, title, ref, stops: [place ids] }`.

`tests/study-content.test.js` checks all of it:
- every reference exists, using KJV verse counts;
- outlines cover their books;
- every place id exists and has a Russian name where a map labels it;
- every text has both English and Russian.

Run `node tools/build-study.mjs` after editing.
